# 科研工作区：科学优先，结构从简

目标：让研究者快速回答“为什么做、用了什么数据、如何运行、结果在哪里、图对应哪个结果、哪些尚未完成”。工作区服务于科学分析和写作，不是建设数据治理平台。

## 先确定范围，不机械套目录

1. 读取用户指定的架构/研究计划、论文、审稿意见，以及与拟建模块相关的旧代码和真实数据说明。先检查文件是否存在；缺失的关键材料明确记为待补，不编造其内容。
2. 区分本次是设计目录、创建工作区、建立环境，还是执行分析。仅要求建工作区时，不下载大数据、训练模型、重新计算实验、发布GitHub或搬移旧数据。
3. 以科学问题、实验对照和交付结果划分模块，而非每个技术动作一个模块。明确样本、统计单位、组别、主要比较、混杂因素以及模块依赖；不把细胞数或技术重复默认当独立样本量。
4. 区分新建、返修/重建和接续：新建按需设计；返修按科学问题与用户要求确定重分析范围；接续优先继承经过核查的成果。用户要求全部重算时遵守该范围，否则不因更换工作区就推翻已完成工作。旧代码不是正确性依据；继承的原始数据、结果和模型注明来源及限制，不得复制旧图旧表冒充新分析。目录创建不等于实验完成。
5. 宣布将创建的主目录、模块划分和环境策略，然后实施用户已授权的部分。只询问会实质改变科学设计或覆盖现有文件的选择，不为命名细节反复阻断。

如涉及具体生物学分析，发现并读取当前环境可用的相关bio skill，再决定方法或执行；不要编造已调用的skill。纯目录规划无需强行调用无关分析技能。

## 最小结构

默认只需要一个总入口、共享数据入口和实际有用的分析模块。例如：

```text
project-slug/
├── README.md
├── data/                    # 共享原始数据；大数据也可仅在README登记外部位置
├── M01_cohort-definition/
│   ├── README.md
│   ├── src/
│   ├── results/
│   └── .venv/               # 真正创建的模块Python环境；不入Git
└── M02_primary-analysis/
    ├── README.md
    ├── src/
    ├── results/
    ├── figures/             # 有绘图任务才创建
    └── .venv/
```

这只是可裁剪示例，不固定模块数量或学科流程。一般从根目录到工作文件控制在2–3层；只有格式要求或确实改善使用才增加层级。不预建空的cache、audit、release、logs、manifest、checkpoint树。

- 总README就是人类与agent的入口：项目目标、材料位置、模块表、依赖顺序、当前状态、推荐起点、环境/数据访问约束。
- 模块README保存该模块的科学合同和运行说明，按[精简模板](references/workspace-template.md)填写；此模板应在生成README前阅读。
- 原始数据指定唯一权威来源且保持只读，模块引用其路径而非各自维护副本。这不禁止必要备份；冷归档只有一份实物时不能称为冗余备份。外部大数据记录实际路径与访问条件，避免软链接被当成可覆盖输出。
- 下游读取上游指定结果，不私自修改上游结果。交接时明确实际配套的数据、预处理、特征名称与顺序、参考对象、模型和输出单位/分母（按任务适用）；路径存在或维度相同不代表可以互换。
- 已冻结、用于报告或被下游消费的结果不原位覆盖。修复以有明确用途的新结果保留，简要记录问题证据、受影响的消费者及必须重跑/仍可复用的部分；不默认重开整个项目，也不为每次小修复制完整目录。
- 图的数据表和绘图代码留在产出它的模块。仅当投稿需要统一打包时建立一个投稿图表导出目录，并保留来源对应关系，不再复制一套分析树。

## 命名与唯一入口

- 项目选一个稳定短名；模块采用唯一编号加明确主题，如`M02_differential-expression`。主题可用中文，但脚本/CLI路径优先简短ASCII；不要同时维护中英文双份目录。
- 已引用的模块编号不因排序变化随意重编。按自然执行顺序展示，但允许独立模块并行。
- 科学文件名包含稳定模块编号和用途，例如`M02_design.tsv`、`M02_fit_model.R`、`M02_primary_contrast.tsv`、`M02_effects.pdf`。论文图号在README或投稿导出时映射，不用图号作为底层结果的唯一身份；调整图序无需重命名分析链。不要使用“最终版”“最终最终”“新建文件夹”“副本2”。
- README、requirements.txt、pyproject.toml、renv.lock等标准文件名可重复，其唯一身份是完整相对路径；不要为形式上的全局唯一破坏工具约定。
- 唯一的是清晰的查询入口，不一定只有一个候选。并行方法使用稳定候选名或短run ID，注明用途、差别和配套资产，不默认最新版本就是最优版本。比较结论注明是否使用相同数据划分、目标定义与评价流程；不因目录整理擅自淘汰或融合候选。不为每次检查生成新版总结或复制整棵目录。

## 必须保留的科学信息

用README中的简短表格或段落即可，不默认另建manifest：

- 分析目的、研究假设、主要比较和预期用于哪幅图/哪个审稿问题。
- 数据来源：研究/数据库编号、官方URL、本地路径、数据版本或获取日期；登记样本分组、排除规则、独立统计单位和共享样本关系。
- 输入：真实路径、必要的列/索引/单位、与上游的对应关系。尚未到位的文件标记“未生成/待获取”，不造空文件冒充输入。
- 方法：关键步骤、核心参数、适用时的随机种子、多重检验、批次/混杂处理和防泄漏边界。没有科学依据时标记待定，不填看似严谨的任意阈值。
- 执行：工作目录、解释器/环境、可复制的命令或明确notebook执行顺序。未试跑的命令标记未验证。
- 输出：主要结果文件、列含义、绘图脚本、图源数据及与论文结论的对应关系。
- 状态分清三件事：程序是否运行成功、证据支持何种结论、下游是否可用。实现错误、证据不足、方法在特定评价下无效、尚未执行不能混为一谈；原因不明则保留不确定性。用简短文字保留阴性结果、限制和下一步，不必另建状态系统。

一次即可形成“源数据/样本 → 分析脚本与关键参数 → 结果表 → 绘图代码 → 图/论点”的可读链条。无需每层重复建索引。文件很多、README表格确实难维护时，才增加一张明确用途的TSV索引，并让README引用它而非抄写其全部内容。

## 模块环境与Windows/WSL

- 新建项目的Python分析模块默认独立`.venv`；接续项目已有明确环境约束时优先继承，并记录每个模块的实际解释器。不要为形式统一复制多个大型深度学习环境；确需改变环境策略时说明兼容性和存储代价，按用户授权执行。共享既有环境不等于允许任意升级其依赖；有冲突时为受影响模块提议隔离环境。运行时不依赖全局activate状态，不向全局环境批量安装依赖。
- 建立可执行方案前检查可用内存、CPU/GPU及显存、磁盘余量和数据所在介质，记录实际约束与待核实项；仅检查能力，不自动启动训练。不要写死某台机器的batch size；沙箱看不到硬件时先核查访问权限，不直接判定硬件不存在或重装驱动。
- 创建时先核查可用解释器及版本是否满足方法要求。可以用合适解释器执行`python -m venv <模块>/.venv`。有`requirements.txt`时再用该环境的`python -m pip`安装；不要将自动下载/安装整个重环境视为建目录的必需步骤。
- 简单Python模块用一份精简requirements；已有合理pyproject则沿用，不并列制造多套依赖清单。核心科学库在实际验证后记录版本，安装前的建议版本不能声称已验证。
- R模块的venv不能隔离R依赖：使用模块独立的renv项目或专用R库，记录R版本和关键包版本；混合模块同时隔离Python与R。确需conda/容器/CUDA工具链时说明原因，遵循用户已批准的环境约束，不强制替换它们。
- 依赖锁文件只在实际锁定依赖有必要时使用，例如renv.lock；禁止每一步生成无用途的“完成锁”。建立目录但未创建环境时诚实标记“环境待创建”，不造空`.venv`冒充成功。
- Windows与WSL的环境不能互相复制使用。Windows用`.venv/Scripts/python.exe`，WSL用`.venv/bin/python`；R调用同样明确所属系统。
- 在WSL分析时，建立一个清楚的Linux母目录和相同模块编号，优先把高频计算放在Linux文件系统；低频原始包/历史大文件可登记冷存储位置，实际迁移须另获授权。总README登记Windows与WSL路径对应、唯一执行工作区、冷热数据访问条件；不要无说明地维护两份可编辑源码/结果。用户指定挂载盘运行时说明性能限制并尊重选择。WSL内部可用空间与宿主承载盘余量分开核查，不能互相替代。
- 不默认搬迁数据或创建符号链接；需要时说明读写行为。不要向冷归档链接写入输出。原始数据、隐私样本及锁定验证数据继续遵守原来的权限与用途限制。

## 克制的复现记录

- 默认不计算MD5/SHA等文件哈希，不生成checksum清单。普通复查使用路径、文件数量、大小、Git差异及必要内容检查；仅上位指令或当前实际使用的技能/工具明确要求时，对必要范围处理。
- 不生成逐步审计子目录、重复总结、自动全量环境转储、无意义日志。必要日志应能回答“失败在哪里/如何复跑”，不收集凭据或敏感样本内容。
- 中间文件只有计算昂贵、科学复核必需或被明确下游使用才保留。建工作区时不生成checkpoint；真正训练时再按恢复需求设置有限保留策略。
- 保存关键随机种子、关键参数、影响结果的软件版本及数据来源；不要将所有机器细节都视为必须归档。
- Git只管理代码和适宜公开的轻量文档。`.venv`、私密数据、凭据、大矩阵和checkpoint不入Git。使用本技能不自动授权创建仓库或公开数据。

## 完成检查与交付

创建后检查实际目录、唯一编号、输入位置、模块依赖、结果与图源对应、README相对链接、环境状态及未完成项。已有目录先检查后补齐，重复执行不覆盖用户代码/结果，也不重建已有环境。

能安全轻量验证时，检查模块解释器、必要包导入和入口可达性；不得为了验收目录而跑整套耗时实验。Python/R生物学方法需要相应分析技能与科学复核，不以结构检查代替。

最后简要给出工作区路径、模块与执行顺序、哪些实际完成、哪些仍缺输入/环境。接手者应能判断哪些成果可直接使用、哪些仅供探索参考、哪些已失效，以及下一步最小可执行任务。通常更新已有README即可，不另生成重复的“最终审计报告”。
